# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CARD ("Calibrating Accelerated Radiometric Decay", formerly RIAG) is a research project modeling time-varying (accelerated) radiometric decay rates within a young-earth creation framework. It converts between "true" young-earth ages and apparent "secular" ages under a piecewise decay-rate model, and fits model parameters to age constraints via MCMC.

`docs/paper/CARD_model.qmd` is the Quarto write-up (math derivations + embedded Python that **imports the package** — its chronology, figures and calibration all come from `card`, so paper and code cannot drift); the `card` package does the real numerics. The restructuring plan and status live in `repo_todo.md`, which is **gitignored** (local planning file, as are `todo.md`/`notes.md`) — they exist only in the original working copy, not in fresh clones.

## Layout

- `src/card/` — the installable package (`pip install -e .` → `import card`), split by concern on 2026-07-26:
  - `chronology.py` — `Chronology` config, `DEFAULT_CHRONOLOGY`, DATE/AGE conversions. No numpy.
  - `constants.py` — numerical settings plus chronology conveniences.
  - `parameters.py` — `ParamSpec` metadata (symbol, unit, bounds, log-scale, description) and helpers. Stdlib only.
  - `models.py` — `DecayModel` ABC, `ConstantDecayModel`, `GeneralModel`, `GeneralModelParams`. **Stdlib only** since 2026-08-05 (see `_solvers.py`); the sole exception is the `quad` fallback in `DecayModel.compute_integral`, which imports scipy inside the method and is unreachable for the two concrete models.
  - `calibrate.py` — deterministic solves from matched date pairs. **Stdlib only.**
  - `_solvers.py` — `brentq`, a port of scipy's `Zeros/brentq.c` that returns bit-identical results. Private. Exists so `models.py`/`calibrate.py` need no scipy: in a Pyodide build the numpy + scipy wheels are 16 MB against a 5.8 MB Python runtime, and the model path used numpy only as a slower spelling of `math.exp`/`math.expm1`/`math.isfinite`. Type checks use `numbers.Real`, which numpy scalars satisfy by ABC registration, so callers passing numpy values are unaffected. Do not add general-purpose numerics here — anything needing real scipy should import it lazily at its use site.
  - `inference.py` — `MCMCFitter` (emcee) + HDF5 chain io. emcee/h5py imported inside methods.
  - `plotting.py` — the only core module importing matplotlib; age curves plus the styled MCMC corner/trace/summary figures.
  - `config.py` — `RunConfig`/`Constraint`/`SamplerConfig`: a whole fit described by a YAML or JSON file. Stdlib + chronology only (`yaml` is imported inside the loader), so a frontend can validate a config without the numerical stack.
  - `cli.py` — the `card` entry point (`card init|fit|calibrate|schema`). Each command imports its own heavy deps, so `card --help` stays fast.
  - `data/flood_only.yaml` — the bundled example run config, declared as package-data in `pyproject.toml` and written out by `card init`. `config.example_config_text()` reads it via `importlib.resources`; `tests/test_docs.py` pins it against the YAML block in `docs/cli.md`, so the documented config and the shipped one cannot diverge.
  - `decay_solver.py`, `card_mcmc.py`, `create_custom_plots.py` — **deprecated shims** re-exporting the above with a `DeprecationWarning`. Do not add to them.
  - `__init__.py` — **lazy** (PEP 562 `__getattr__`). `import card` costs ~1.4 ms and loads no numpy/scipy/matplotlib/emcee; each name resolves on first access. To export a new name, add one row to `_EXPORTS` (and the `TYPE_CHECKING` block for IDEs). Do not add eager top-level imports — `tests/test_package_structure.py` asserts nothing heavy is loaded.
- `tests/` — pytest suite.
- `examples/` — driver/figure scripts (`run_card_mcmc.py`, `plot_model_calibration*.py`, `demo_parameter_sweep.py`, `plot_general_model.py`); they import the installed `card` package and write outputs (PNGs, `mcmc_output/`) to the current working directory. **`examples/` is not installed by pip**, which is why the worked run config lives in `src/card/data/flood_only.yaml` (package data) and is written out by `card init` rather than being read from the repo.
- `docs/` — the mkdocs-material site (`mkdocs.yml` at the repo root): `index.md`, `model.md`, `cli.md`, `gallery.md`, `tutorials/`, and `api/` (one `::: card.<module>` stub per module, rendered by mkdocstrings). `docs/generate_figures.py` runs the example scripts into `docs/img/` for the gallery; those PNGs are gitignored and regenerated by CI, so a local `mkdocs serve` without running it shows alt text.
- `docs/paper/` — the Quarto paper. Excluded from the mkdocs site via `exclude_docs`.
- `.github/workflows/tests.yml` — CI: pytest on ubuntu + macos, Python 3.10–3.14, on push to main and on every PR.
- `.github/workflows/docs.yml` — builds the site (`mkdocs build --strict`) on every PR and publishes it to GitHub Pages from main.

## Environment and Commands

- Setup: `python3 -m venv .venv && .venv/bin/pip install -e ".[dev,docs]"` (deps in `pyproject.toml`). `pyyaml` is now a core dependency (run configs), which also satisfies Quarto's bootstrap; the `docs` extra carries `jupyter` and keeps `pyyaml` listed so the reason it is needed for rendering stays visible. The checkout now lives outside Dropbox, so an in-repo `.venv` is fine (it is gitignored).
- The root scripts and tests import the `card` package, so the package must be installed (editable install above) — there is no sys.path hack.
- Run the unit tests: `python -m pytest` (config in `pyproject.toml`).
- Run the main MCMC inversion (writes to `mcmc_output/`): `python examples/run_card_mcmc.py`, or the config-driven equivalent `card init myrun.yaml && card fit myrun.yaml` (`--steps`/`--walkers`/`--seed`/`--no-figures` override the file; `card calibrate myrun.yaml` solves the same two constraints exactly, in milliseconds).
- Build the docs: `mkdocs serve` to preview, `mkdocs build --strict` to check (strict is what CI runs — a broken link or an undocumented parameter fails it). `python docs/generate_figures.py` first if you want the gallery images locally.
- Render the paper: activate the venv first (`source .venv/bin/activate`), then `quarto render docs/paper/CARD_model.qmd`. Quarto picks the interpreter from the active virtualenv; without it it falls back to a system `python3` that lacks `yaml`/`jupyter`. Produces HTML and PDF; render artifacts are gitignored.

## Time and Normalization Conventions (critical)

- Two time conventions coexist, and **the name of a quantity says which one it uses** (rule established 2026-07-26, documented in `chronology.py`):
  - **`*_DATE`** — years after Day 1 of Creation (forward time `t`). Model parameters `t_c`/`t_F`/`t_F2` and `lambda_func(t)` are DATEs.
  - **`*_AGE`** — years before present (YBP, `tau`). Everything into or out of `forward_age`/`inverse_age`, and all `CARDMCMC` data ages, are AGEs.
  - A DATE and its matching AGE sum to `AGE_OF_EARTH`; `tests/test_chronology.py` pins these relationships so a refactor cannot silently flip one.
- Chronology values are **user-specifiable modeling assumptions, not constants**: the frozen `Chronology` dataclass in `chronology.py` holds `age_of_earth` (6056), `flood_start_date`/`flood_end_date` (1656), `ice_age_end_date` (3500), derives the matching AGEs as properties, and loads/saves JSON config files. `DEFAULT_CHRONOLOGY` backs the convenience constants in `constants.py` (`AGE_OF_EARTH`, `FLOOD_START_DATE`, `FLOOD_END_DATE`, `FLOOD_AGE` = 4400, `ICE_AGE_END_DATE` = 3500, `ICE_AGE_END_AGE` = 2556). MCMC results generated before 2026-07-19 fit the Ice Age at 3500 YBP instead of 2556 and are stale.
- Removed 2026-07-26: `FLOOD_START`/`FLOOD_END` (now `*_DATE`), `ICE_AGE_END_YBP` (now `ICE_AGE_END_AGE`), and `PC_CAMBRIAN_BOUNDARY` (was labeled years-after-Creation but the paper used 5400 as YBP; it matched neither current constant and had no callers). Note `ICE_AGE_END_AGE` **kept its name but changed meaning** — it is now 2556 (YBP), not 3500.
- `GeneralModelParams` validates on construction: all lambdas >= 1 (rates are multiples of background), `k_c`/`k_F` >= 0 (the minus sign is already in `exp(-k*dt)`, so positive k is what decays; k=0 is the no-relaxation limit), dates ordered `t_c <= t_F <= t_F2` (equality of the last pair is the instantaneous-Flood limit), and a warning when the Flood exceeds `MAX_UNREMARKED_FLOOD_DURATION` (2 years) or when `lambda_bg != 1` (which is normalized to 1 rather than rejected). `CARDMCMC.log_likelihood` catches `ValueError` specifically, which is how these bounds reach the sampler — do not widen it back to `except Exception`.

## Architecture

- **src/card/models.py** — the numerical core. `DecayModel` is a real ABC: a subclass supplies `lambda_func`, optionally `breakpoints()` (the DATEs where lambda jumps), and inherits working `compute_integral` (quad, subdivided at those breakpoints), `forward_age`, `max_secular_age` and `inverse_age`. `ConstantDecayModel` and `GeneralModel` each override `compute_integral` with a closed form. The flood-only limit is built via `GeneralModel.flood_only(lambda_F, k_F, t_F=...)` (the old standalone `FloodOnlyModel`, whose post-Flood exponential was anchored at the present, was removed 2026-07-19). Parameters travel in the `GeneralModelParams` dataclass, which validates in `__post_init__` and offers `to_dict`/`from_dict`.
  - **Error contract, uniform across all models**: invalid input raises `ValueError` — never a NaN sentinel, never a plausible number. Ages must be finite, >= 0, and <= `present_time`; `inverse_age` also rejects secular ages above `max_secular_age()`. `forward_age` used to return NaN for negative ages purely to placate the old `fsolve` inverse; that is gone and must not come back. `compute_integral` always returns the **normalized** integral of lambda/lambda_bg.
  - **src/card/plotting.py** — `plot_age_comparison`, `plot_general_model_parameter_sweep`, `plot_lambda_history` (λ(t) against DATE — the only figure whose x axis is a DATE rather than an AGE). All take an optional `ax` so a GUI can draw into its own canvas, and an optional `return_figure=True` to get the matplotlib `Figure` back **open** (what `st.pyplot`, a Qt canvas or a notebook wants) instead of a path. Opt-in, so the default path-returning behavior is unchanged. Never call `matplotlib.use()` here: an earlier version forced "Agg" at call time, which overrode a host application's backend process-wide and made `show=True` silently do nothing.
  - `GeneralModel.compute_integral` evaluates the piecewise integral in **closed form** (every region is constant or a decaying exponential) rather than by quadrature, and `inverse_age` uses a bracketed `brentq` solve on `[0, present_time]`. Both replaced numerical approximations on 2026-07-26: `quad` without breakpoints misplaced up to 0.8% of integrals spanning the Flood discontinuity and made `forward_age` non-monotone, which in turn made the old `fsolve` inverse fail on up to 17% of targets. Do not reintroduce quadrature here; if a future model has no closed form, give the base class a `quad` fallback that is passed the model's breakpoints.
- **tests/** — `test_models.py` (round-trip, monotonicity, error contract), `test_characterization.py` (pins known-good numbers; if a deliberate model change shifts them, re-pin in the same commit), `test_validation.py` (every `GeneralModelParams` rule), `test_chronology.py` (the DATE/AGE relationships), `test_package_structure.py` (lazy imports, the deprecation shims, the new-model extension path, and **that the model path imports no numpy/scipy** — including one test that blocks both via `sys.meta_path` and runs a full solve anyway), `test_parameters.py`, `test_calibrate.py` (pins the recorded calibration solutions), `test_solvers.py` (asserts `_solvers.brentq` is bit-for-bit equal to scipy's, which is why the swap re-pinned no characterization numbers), `test_inference.py`, `test_plotting.py`, `test_config.py` (run-config parsing and validation), `test_mcmc_smoke.py` (the whole config → chain → figures path at 8 walkers × 60 steps, ~3 s; keep it that fast — it is the only CI coverage of the MCMC pipeline), `test_docs.py`.
- **`tests/test_docs.py` executes the documentation.** Every ```python block in `docs/` runs (one namespace per page, in a subprocess with a scratch cwd), and when a ```python block is followed by a ```text block, that text is compared to its stdout exactly. So **any number printed in the docs is a pinned value**: change the model and the tutorials fail until they are re-run. Mark a block `# docs: skip` on its first line to show it without running it; ```bash/```yaml blocks are never run. The same principle now covers `card/__init__.py`'s `>>>` example via `doctest.testmod` in `test_package_structure.py` — it had been advertising 537313592 for a Flood secular age of 533337567 ever since the closed-form integral landed, because nothing ran it.
- **src/card/parameters.py** — the extensibility keystone. Each parameter is declared once, as a `ParamSpec` in its dataclass field metadata, and the fitter, plots, and any GUI read that instead of keeping their own lists. A spec with `minimum == maximum` is **not fittable** (`lambda_bg`), so fitters and sliders skip it structurally rather than by hardcoded exclusion. `to_json_schema()` renders the specs for a browser form. A spec also carries `is_date`, because a DATE's upper bound is the age of the Earth — a chronology setting, not a constant: `bounds_for_chronology(params_class, chronology)` and `to_json_schema(..., chronology=...)` return date bounds that follow the loaded chronology instead of the one frozen in at import time.
- **src/card/calibrate.py** — deterministic alternative to MCMC. `solve_lambda_F` (one pair, fixed k_F) and `solve_flood_only` (two pairs, both unknowns) return a `CalibrationResult` carrying the model and per-constraint residuals. The joint solve is **nested bracketed 1-D solves**, not a 2-D `fsolve`: for any k_F the Flood constraint pins lambda_F by a monotone root, leaving one equation in k_F with a guaranteed sign change. The old `fsolve` version silently diverged to `lambda_F ~ 1e-8` on chronologies its hardcoded initial guess did not suit. Do not reintroduce an initial guess here.
- **src/card/inference.py** — `MCMCFitter` (the old `CARDMCMC`). Which parameters exist, whether each is sampled in log10, and the default priors all come from the parameter spec. **Sampling space is per-parameter**: `log_scale=True` (the lambdas and k's) are sampled as `10**theta` with log10 priors; `log_scale=False` (the times) are sampled linearly. `fixed_params` values are always **linear**. Results keep the chain's `(step, walker)` shape and are saved as one self-describing HDF5 file; `backend_path=` streams to HDF5 during the run for resumability.
- **Randomness is per-run, never global** (2026-08-01). `run_mcmc(seed=...)` or `rng=<Generator>` seeds both the initial positions and emcee's own proposals; nothing touches `np.random.seed`, so concurrent fits (a web service, two GUI tabs) cannot disturb each other and an unrelated global reseed cannot change a "reproducible" run. `run_mcmc(callback=...)` receives a `SamplingProgress` (phase, step, total, `fraction`, acceptance) after every step and **returning False stops the run**; the results then carry `stopped_early=True`, `n_steps` = steps actually taken, and `n_steps_requested`. Both exist for GUI progress bars and cancel buttons. `present_time=` (default `AGE_OF_EARTH`) is what makes a non-default chronology load-bearing — without it the data ages come from the config's chronology while `forward_age` measures against the default one.
- **src/card/config.py + cli.py** — a fit described by a file instead of a script. `card fit config.yaml` reproduces the driver's outputs plus `run_config.json` (the resolved config, the only complete record of a run). Anywhere a number is expected the config also accepts a chronology *name*, and the `_age`/`_date` suffix carries the convention, so `t_F: flood_start_date` is self-checking where `t_F: 1656` is not. Unknown keys are rejected, not ignored. Numeric-looking strings are accepted because YAML 1.1 reads `540.0e6` as a string (it wants `540.0e+6`).
- **examples/run_card_mcmc.py** — the main driver. Fits the flood-only limit (fixes `lambda_c`, `k_c`, `t_c`, `t_F`, `t_F2`; frees `lambda_F`, `k_F`) against two constraints: Flood rocks (4400 YBP) appear 540 Myr old, Ice-Age-end rocks (2556 YBP) appear 11.5 kyr old. Writes `chain.h5` plus figures and `summary_statistics.txt` to `mcmc_output/`.
- **This posterior is bimodal, and the second mode is a trap.** Besides the real solution there is a local maximum at tiny `lambda_F` with `k_F` small enough that the rate never relaxes; it fits the tight Ice Age constraint and misses the Flood by ~50 sigma. Started from the prior means, ~9 of 32 walkers fall into it during burn-in and can never leave (the barrier is ~1e10 in log-posterior), which silently dragged the reported 16th percentile of `lambda_F` from 3.2e6 to 5.4. **Always start the walkers at the exact solve** — `initial_guess=` from `solve_flood_only`, or `sampler.initial_guess: calibrate` in a run config. `MCMCFitter._find_stuck_walkers` warns (and `results['stuck_walkers']` records it) when any walker sits `STUCK_WALKER_LOG_PROB_GAP` (50) below the best; it never discards samples. A converged run of this fit has acceptance ~0.72 and autocorrelation ~33, versus 0.38 and ~950 for a contaminated one.
- **MCMC figures** live in `plotting.py`: `plot_mcmc_corner`, `plot_mcmc_traces`, `summarize_mcmc`. `summarize_mcmc` reports each parameter in **both** spaces — `median` is the sampled value, `linear_median` the model value. Use the `linear_*` keys when feeding posteriors back into a model; passing the raw `mean` of a log10-sampled parameter is a real bug the driver used to have (it plotted `lambda_F = 6.5` instead of `3.2e6`). `load_legacy_text_results` still reads pre-HDF5 `mcmc_output/` directories, inferring the walker count the old format did not record.
- **examples/plot_model_calibration.py**, **examples/plot_model_calibration_joint.py** — figure scripts for the two calibration scenarios; the solves themselves now come from `card.calibrate`, and the solved values are pinned in `tests/test_calibrate.py`. Each is now self-contained (the joint one used to import its constants from the fixed-`k_F` one, which only resolved when run from inside `examples/`); scripts still write their PNGs to the current directory.
- **examples/demo_parameter_sweep.py**, **examples/plot_general_model.py** — standalone plot generators. Both call the package: `plot_general_model.py` and the paper's `fig-general-model` now share `plotting.plot_lambda_history`, so the λ(t) schematic is drawn by one piece of code that evaluates `GeneralModel.lambda_func`. It previously hand-rolled the piecewise formula with its own Flood date and its own age of the Earth.
