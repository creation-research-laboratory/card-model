# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CARD ("Calibrating Accelerated Radiometric Decay", formerly RIAG) is a research project modeling time-varying (accelerated) radiometric decay rates within a young-earth creation framework. It converts between "true" young-earth ages and apparent "secular" ages under a piecewise decay-rate model, and fits model parameters to age constraints via MCMC.

`docs/paper/CARD_model.qmd` is the Quarto write-up (math derivations + embedded Python that **imports the package** — its chronology, figures and calibration all come from `card`, so paper and code cannot drift); the `card` package does the real numerics. The restructuring plan and status live in `repo_todo.md`, which is **gitignored** (local planning file, as are `todo.md`/`notes.md`) — they exist only in the original working copy, not in fresh clones.

## Layout

- `src/card/` — the installable package (`pip install -e .` → `import card`), split by concern on 2026-07-26:
  - `chronology.py` — `Chronology` config, `DEFAULT_CHRONOLOGY`, DATE/AGE conversions. No numpy.
  - `constants.py` — numerical settings plus chronology conveniences.
  - `parameters.py` — `ParamSpec` metadata (symbol, unit, bounds, log-scale, description) and helpers. Stdlib only.
  - `models.py` — `DecayModel` ABC, `ConstantDecayModel`, `GeneralModel`, `GeneralModelParams`. numpy + scipy only.
  - `calibrate.py` — deterministic solves from matched date pairs. scipy only.
  - `inference.py` — `MCMCFitter` (emcee) + HDF5 chain io. emcee/h5py imported inside methods.
  - `plotting.py` — the only core module importing matplotlib; age curves plus the styled MCMC corner/trace/summary figures.
  - `config.py` — `RunConfig`/`Constraint`/`SamplerConfig`: a whole fit described by a YAML or JSON file. Stdlib + chronology only (`yaml` is imported inside the loader), so a frontend can validate a config without the numerical stack.
  - `cli.py` — the `card` entry point (`card fit|calibrate|schema`). Each command imports its own heavy deps, so `card --help` stays fast.
  - `decay_solver.py`, `card_mcmc.py`, `create_custom_plots.py` — **deprecated shims** re-exporting the above with a `DeprecationWarning`. Do not add to them.
  - `__init__.py` — **lazy** (PEP 562 `__getattr__`). `import card` costs ~1.4 ms and loads no numpy/scipy/matplotlib/emcee; each name resolves on first access. To export a new name, add one row to `_EXPORTS` (and the `TYPE_CHECKING` block for IDEs). Do not add eager top-level imports — `tests/test_package_structure.py` asserts nothing heavy is loaded.
- `tests/` — pytest suite.
- `examples/` — driver/figure scripts (`run_card_mcmc.py`, `plot_model_calibration*.py`, `demo_parameter_sweep.py`, `plot_general_model.py`); they import the installed `card` package and write outputs (PNGs, `mcmc_output/`) to the current working directory. `flood_only.yaml` is the run-config form of `run_card_mcmc.py`.
- `docs/paper/` — the Quarto paper.
- `.github/workflows/tests.yml` — CI: pytest on ubuntu + macos, Python 3.10–3.13, on push to main and on every PR.

## Environment and Commands

- Setup: `python3 -m venv .venv && .venv/bin/pip install -e ".[dev,docs]"` (deps in `pyproject.toml`). `pyyaml` is now a core dependency (run configs), which also satisfies Quarto's bootstrap; the `docs` extra carries `jupyter` and keeps `pyyaml` listed so the reason it is needed for rendering stays visible. The checkout now lives outside Dropbox, so an in-repo `.venv` is fine (it is gitignored).
- The root scripts and tests import the `card` package, so the package must be installed (editable install above) — there is no sys.path hack.
- Run the unit tests: `python -m pytest` (config in `pyproject.toml`).
- Run the main MCMC inversion (writes to `mcmc_output/`): `python examples/run_card_mcmc.py`, or the config-driven equivalent `card fit examples/flood_only.yaml` (`--steps`/`--walkers`/`--seed`/`--no-figures` override the file; `card calibrate examples/flood_only.yaml` solves the same two constraints exactly, in milliseconds).
- Render the paper: activate the venv first (`source .venv/bin/activate`), then `quarto render docs/paper/CARD_model.qmd`. Quarto picks the interpreter from the active virtualenv; without it it falls back to a system `python3` that lacks `yaml`/`jupyter`. Produces HTML and PDF; render artifacts are gitignored.

## Time and Normalization Conventions (critical)

- Two time conventions coexist, and **the name of a quantity says which one it uses** (rule established 2026-07-26, documented in `chronology.py`):
  - **`*_DATE`** — years after Day 1 of Creation (forward time `t`). Model parameters `t_c`/`t_F`/`t_F2` and `lambda_func(t)` are DATEs.
  - **`*_AGE`** — years before present (YBP, `tau`). Everything into or out of `forward_age`/`inverse_age`, and all `CARDMCMC` data ages, are AGEs.
  - A DATE and its matching AGE sum to `AGE_OF_EARTH`; `tests/test_chronology.py` pins these relationships so a refactor cannot silently flip one.
- Chronology values are **user-specifiable modeling assumptions, not constants**: the frozen `Chronology` dataclass in `chronology.py` holds `age_of_earth` (6056), `flood_start_date`/`flood_end_date` (1656), `ice_age_end_date` (3500), derives the matching AGEs as properties, and loads/saves JSON config files. `DEFAULT_CHRONOLOGY` backs the convenience constants in `constants.py` (`AGE_OF_EARTH`, `FLOOD_START_DATE`, `FLOOD_END_DATE`, `FLOOD_AGE` = 4400, `ICE_AGE_END_DATE` = 3500, `ICE_AGE_END_AGE` = 2556). MCMC results generated before 2026-07-19 fit the Ice Age at 3500 YBP instead of 2556 and are stale.
- Removed 2026-07-26: `FLOOD_START`/`FLOOD_END` (now `*_DATE`), `ICE_AGE_END_YBP` (now `ICE_AGE_END_AGE`), and `PC_CAMBRIAN_BOUNDARY` (was labeled years-after-Creation but the paper used 5400 as YBP; it matched neither current constant and had no callers). Note `ICE_AGE_END_AGE` **kept its name but changed meaning** — it is now 2556 (YBP), not 3500.
- `GeneralModelParams` validates on construction: all lambdas >= 1 (rates are multiples of background), `k_c`/`k_F` >= 0 (the minus sign is already in `exp(-k*dt)`, so positive k is what decays; k=0 is the no-relaxation limit), dates ordered `t_c <= t_F <= t_F2` (equality of the last pair is the instantaneous-Flood limit), and a warning when the Flood exceeds `MAX_UNREMARKED_FLOOD_DURATION` (2 years) or when `lambda_bg != 1` (which is normalized to 1 rather than rejected). `CARDMCMC.log_likelihood` catches `ValueError` specifically, which is how these bounds reach the sampler — do not widen it back to `except Exception`.

## Architecture

- **src/card/models.py** — the numerical core. `DecayModel` is a real ABC: a subclass supplies `lambda_func`, optionally `breakpoints()` (the DATEs where lambda jumps), and inherits working `compute_integral` (quad, subdivided at those breakpoints), `forward_age`, `max_secular_age` and `inverse_age`. `ConstantDecayModel` and `GeneralModel` each override `compute_integral` with a closed form. The flood-only limit is built via `GeneralModel.flood_only(lambda_F, k_F, t_F=...)` (the old standalone `FloodOnlyModel`, whose post-Flood exponential was anchored at the present, was removed 2026-07-19). Parameters travel in the `GeneralModelParams` dataclass, which validates in `__post_init__` and offers `to_dict`/`from_dict`.
  - **Error contract, uniform across all models**: invalid input raises `ValueError` — never a NaN sentinel, never a plausible number. Ages must be finite, >= 0, and <= `present_time`; `inverse_age` also rejects secular ages above `max_secular_age()`. `forward_age` used to return NaN for negative ages purely to placate the old `fsolve` inverse; that is gone and must not come back. `compute_integral` always returns the **normalized** integral of lambda/lambda_bg.
  - **src/card/plotting.py** — `plot_age_comparison`, `plot_general_model_parameter_sweep`. Both take an optional `ax` so a GUI can draw into its own canvas. Never call `matplotlib.use()` here: an earlier version forced "Agg" at call time, which overrode a host application's backend process-wide and made `show=True` silently do nothing.
  - `GeneralModel.compute_integral` evaluates the piecewise integral in **closed form** (every region is constant or a decaying exponential) rather than by quadrature, and `inverse_age` uses a bracketed `brentq` solve on `[0, present_time]`. Both replaced numerical approximations on 2026-07-26: `quad` without breakpoints misplaced up to 0.8% of integrals spanning the Flood discontinuity and made `forward_age` non-monotone, which in turn made the old `fsolve` inverse fail on up to 17% of targets. Do not reintroduce quadrature here; if a future model has no closed form, give the base class a `quad` fallback that is passed the model's breakpoints.
- **tests/** — `test_models.py` (round-trip, monotonicity, error contract), `test_characterization.py` (pins known-good numbers; if a deliberate model change shifts them, re-pin in the same commit), `test_validation.py` (every `GeneralModelParams` rule), `test_chronology.py` (the DATE/AGE relationships), `test_package_structure.py` (lazy imports, the deprecation shims, the new-model extension path), `test_parameters.py`, `test_calibrate.py` (pins the recorded calibration solutions), `test_inference.py`, `test_plotting.py`, `test_config.py` (run-config parsing and validation), `test_mcmc_smoke.py` (the whole config → chain → figures path at 8 walkers × 60 steps, ~3 s; keep it that fast — it is the only CI coverage of the MCMC pipeline).
- **src/card/parameters.py** — the extensibility keystone. Each parameter is declared once, as a `ParamSpec` in its dataclass field metadata, and the fitter, plots, and any GUI read that instead of keeping their own lists. A spec with `minimum == maximum` is **not fittable** (`lambda_bg`), so fitters and sliders skip it structurally rather than by hardcoded exclusion. `to_json_schema()` renders the specs for a browser form.
- **src/card/calibrate.py** — deterministic alternative to MCMC. `solve_lambda_F` (one pair, fixed k_F) and `solve_flood_only` (two pairs, both unknowns) return a `CalibrationResult` carrying the model and per-constraint residuals. The joint solve is **nested bracketed 1-D solves**, not a 2-D `fsolve`: for any k_F the Flood constraint pins lambda_F by a monotone root, leaving one equation in k_F with a guaranteed sign change. The old `fsolve` version silently diverged to `lambda_F ~ 1e-8` on chronologies its hardcoded initial guess did not suit. Do not reintroduce an initial guess here.
- **src/card/inference.py** — `MCMCFitter` (the old `CARDMCMC`). Which parameters exist, whether each is sampled in log10, and the default priors all come from the parameter spec. **Sampling space is per-parameter**: `log_scale=True` (the lambdas and k's) are sampled as `10**theta` with log10 priors; `log_scale=False` (the times) are sampled linearly. `fixed_params` values are always **linear**. Results keep the chain's `(step, walker)` shape and are saved as one self-describing HDF5 file; `backend_path=` streams to HDF5 during the run for resumability. `present_time=` (default `AGE_OF_EARTH`) is what makes a non-default chronology load-bearing — without it the data ages come from the config's chronology while `forward_age` measures against the default one.
- **src/card/config.py + cli.py** — a fit described by a file instead of a script. `card fit config.yaml` reproduces the driver's outputs plus `run_config.json` (the resolved config, the only complete record of a run). Anywhere a number is expected the config also accepts a chronology *name*, and the `_age`/`_date` suffix carries the convention, so `t_F: flood_start_date` is self-checking where `t_F: 1656` is not. Unknown keys are rejected, not ignored. Numeric-looking strings are accepted because YAML 1.1 reads `540.0e6` as a string (it wants `540.0e+6`).
- **examples/run_card_mcmc.py** — the main driver. Fits the flood-only limit (fixes `lambda_c`, `k_c`, `t_c`, `t_F`, `t_F2`; frees `lambda_F`, `k_F`) against two constraints: Flood rocks (4400 YBP) appear 540 Myr old, Ice-Age-end rocks (2556 YBP) appear 11.5 kyr old. Writes `chain.h5` plus figures and `summary_statistics.txt` to `mcmc_output/`.
- **MCMC figures** live in `plotting.py`: `plot_mcmc_corner`, `plot_mcmc_traces`, `summarize_mcmc`. `summarize_mcmc` reports each parameter in **both** spaces — `median` is the sampled value, `linear_median` the model value. Use the `linear_*` keys when feeding posteriors back into a model; passing the raw `mean` of a log10-sampled parameter is a real bug the driver used to have (it plotted `lambda_F = 6.5` instead of `3.2e6`). `load_legacy_text_results` still reads pre-HDF5 `mcmc_output/` directories, inferring the walker count the old format did not record.
- **examples/plot_model_calibration.py**, **examples/plot_model_calibration_joint.py** — figure scripts for the two calibration scenarios; the solves themselves now come from `card.calibrate`, and the solved values are pinned in `tests/test_calibrate.py`. The joint script imports constants from the fixed-`k_F` one, so run them from `examples/`.
- **examples/demo_parameter_sweep.py**, **examples/plot_general_model.py** — standalone plot generators (plot_general_model.py still hand-rolls its own λ(t) rather than using the package — rewrite pending, see repo_todo.md; the paper's copy of that figure was already switched to `GeneralModel.lambda_func`).
